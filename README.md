# Kanji App

A minimalist kanji + vocabulary study app with spaced repetition. Lives at:

**https://kanji-app-brown-three.vercel.app**

On iPhone: open that URL in Safari → Share → **Add to Home Screen** → launches full-screen with splash screen, service worker offline cache, and no white flash.

## Files in this project

| File / folder | Role |
|---|---|

| `icons/` | App icons: `icon-180.png`, `icon-192.png`, `icon-512.png`. Generated by `build.py` via Pillow. |

| `lib/` | Self-hosted React 18 UMD builds (`react.production.min.js`, `react-dom.production.min.js`). Inlined into index.html at build time. |
| `vercel.json` | Vercel config: rewrites `/` → `index.html`, correct Cache-Control headers (no-cache for SW + HTML, immutable for assets). |
| `pipeline/build.py` | **Main build script.** Runs bundle.py → compiles JSX → inlines React → generates index.html + sw.js + icons + splash screens. Run this before deploying. |
| `pipeline/bundle.py` | Updates the `DECKS` block inside `kanji-app.html`. Called automatically by `build.py`. Run directly when iterating on deck content without a full build. |
| `pipeline/build_decks.py` | Generates per-deck JSON files (Genki 1/2, JLPT N5/N4) from embedded kanji data. Run before `bundle.py` when changing kanji in those decks. |
| `pipeline/out/*.json` | Generated deck files — intermediate, consumed by `bundle.py`. |
| `agent-files/integrated_ch*.json` | Integrated Approach chapter decks. Auto-picked up by `bundle.py`. |

| `study-guides/kimi-no-na-wa/README.md` | How the 君の名は。 decks were built, plus ready-to-paste prompts for an agent to write chapter study guides or refine a deck from page photos. |
| `kanji-app.html.bak` | Backup from the last `bundle.py` run. |
| `package.json` | npm — only dev dep is `@babel/cli` + `@babel/preset-react` for the build step. |
| `.babelrc.json` | Babel config written by `build.py` at build time. |
| `.github/workflows/deploy.yml` | GitHub Actions CD workflow — triggers on push to `main`. |

## For a future agent — how to work on this project

### Two-file architecture

```
kanji-app.html  ← edit this (source, uses Babel CDN for dev)
      │
      └─ python3 pipeline/build.py
                │
                ├─ kanji-app.html (DECKS updated via bundle.py)
                ├─ index.html     (compiled, self-contained — deploy this)
                ├─ sw.js
                ├─ icons/
                └─ splash/
```

**Always edit `kanji-app.html`.** Run `python3 pipeline/build.py` before deploying. Then `vercel --prod` to push.

### Build commands (from project root)

```bash
# Full production build (always run before vercel --prod):
python3 pipeline/build.py

# Content only — faster iteration when just changing deck data:
python3 pipeline/bundle.py

# Kanji data changes (Genki/JLPT decks) need this first:
python3 pipeline/build_decks.py && python3 pipeline/bundle.py

# Deploy to production (manual):
vercel --prod

# Or just push to main — CI/CD handles the rest:
git push origin main
```

### CI/CD — how deploys work

Every push to `main` triggers `.github/workflows/deploy.yml`:

```
git push origin main
        │
        └─ GitHub Actions (ubuntu-latest)
              1. actions/checkout@v4          — clone repo
              2. actions/setup-node@v4        — Node 20 (for Babel CLI)
              3. actions/setup-python@v5      — Python 3.12 (for build.py + Pillow)
              4. pip install pillow           — icon/splash generation
              5. npm ci                       — install @babel/cli + @babel/preset-react
              6. python3 pipeline/build.py    — compile JSX, inline React, write index.html + sw.js + assets
              7. npx vercel --prod            — deploy to Vercel production
```

The workflow authenticates to Vercel via three repository secrets set with `gh secret set`:

| Secret | What it is |
|---|---|
| `VERCEL_TOKEN` | Personal access token from vercel.com/account/tokens |
| `VERCEL_ORG_ID` | Your Vercel team/org ID (`team_vjXi1UpWw9OJEJ0vRyaY5x0R`) |
| `VERCEL_PROJECT_ID` | The Vercel project ID (`prj_JiNLrkU9oUigSHMoSSI74ZT2yEpD`) |

Generated files (`index.html`, `sw.js`, `icons/`, `splash/`) are **not committed** to git — they are produced fresh in CI on every deploy. This keeps the repo lean; the source of truth is `kanji-app.html` and `agent-files/`.

If you need to deploy without waiting for CI (e.g. hotfix), run `python3 pipeline/build.py && vercel --prod` locally.

### What lives where in kanji-app.html

```
kanji-app.html
├── <style>                 All CSS — dark theme, card layout, iOS safe-area
├── React + ReactDOM        CDN (dev only; build.py inlines lib/ for prod)
├── Babel Standalone        CDN (dev only; build.py compiles and removes)
└── <script type="text/babel">
    ├── — DATA —            DECKS array — generated by bundle.py, do not hand-edit
    ├── — END DATA —
    ├── sm2()               Spaced-repetition scheduler
    ├── buildQueue()        Picks due + new cards per session
    ├── loadState/saveState localStorage (key: "kanji-app", schemaVersion: 2)
    └── Components          App → Home | GroupDetail | DeckDetail | Study | Stats | Settings
```

### Never hand-edit the DECKS region

The block between `// — DATA —` and `// — END DATA —` in `kanji-app.html` is overwritten on every `bundle.py` run. Add cards by editing the pipeline files and rebuilding.

### Changing persisted state shape

Bump `SCHEMA_VERSION` in `kanji-app.html` and add a migration to the `MIGRATIONS` map. `loadState` chains migrations automatically, including on imported backups.

```js
const MIGRATIONS = {
  1: (s) => ({ ...s, schemaVersion: 2 }),
  2: (s) => ({ ...s, newField: defaultValue, schemaVersion: 3 }),
};
```

### DECK_GROUPS

Lives just after the `DECKS` constant, outside the `DATA —` region so `bundle.py` won't overwrite it. Defines which deck IDs roll up into a group tile on Home. Add a new textbook group by pushing an entry here.

Optional group fields: `unit` (label for card counts, default `"kanji"` — the 君の名は。 group uses `"words"`) and `chapterLabel(n, decks)` (section heading in the group screen, default `Chapter N`).

## How it works

### SM-2 review scheduling

Each card gets `{ ease, interval, reps, due, lastReview }`. Ratings:

- **Again** → reps reset, ease −0.2 (min 1.3), requeued ~10 min into session
- **Hard** → interval × 1.2, ease −0.15
- **Good** → interval × ease
- **Easy** → interval × ease × 1.3, ease +0.15

New cards graduate at fixed intervals (1d / 1d / 4d), matching Anki's early-review behavior.

### Session queue

`buildQueue` returns: all cards with `due <= now`, then up to `newPerDay` unseen cards. "Again" inserts the card 3 positions ahead in the same session.

### Persistence

```js
// localStorage key: "kanji-app"
{
  schemaVersion: 2,
  progress: { "漢": { ease, interval, reps, due, lastReview }, ... },
  stats:    { byDay: { "YYYY-MM-DD": { reviewed, again, hard, good, easy } } },
  settings: { dailyGoal: 30, newPerDay: 10 },
  streak:   { current, longest, lastActiveDay }
}
```

Progress is keyed by kanji character (or `word` for vocab cards). Settings → Export / Import for backup.

### Screens

- **Home** — Kanji / Vocab tab selector. Streak and daily-goal progress at top.
- **Group detail** — chapter list for a grouped textbook, per-chapter due/new counts, Writing + 読めればいい sub-rows.
- **Deck detail** — stats, Study CTA, card grid. Vocab decks show a JLPT priority filter above the grid. Tap any card to peek; use ← / → to navigate without closing.
- **Study** — flip card (Space/Enter), rate 1–4 (Again/Hard/Good/Easy), undo (U). Vocab card fronts show the word at readable size + kana; backs show Reading / Category / Context.
- **Stats** — last 7 days, totals, accuracy, streak.
- **Settings** — daily goal, new cards/day, export, import, reset.

## Adding content

### Add kanji to an existing deck (Genki 1/2, JLPT N5/N4)

1. Edit `pipeline/build_decks.py` — find the deck section, add a `k(...)` call.
2. `python3 pipeline/build_decks.py && python3 pipeline/build.py`

### Add an Integrated Approach chapter

1. Create `agent-files/integrated_chN.json`:
   ```json
   { "deck_id": "integrated-intermediate-chN",
     "deck_name": "An Integrated Approach — Ch.N Kanji",
     "card_count": 42,
     "cards": [{ "kanji": "漢", "meanings": [...], "on_yomi": [...], "kun_yomi": [...],
                 "examples": [...], "keyword": "...", "etymology": "...",
                 "stroke_count": 13, "jlpt": "N3", "grade": 2, "decks": ["..."] }] }
   ```
2. `python3 pipeline/build.py` — chapter auto-appears under An Integrated Approach on Home.

### Add a vocabulary deck

1. Create `agent-files/vocab_<name>.json`:
   ```json
   { "deck_id": "vocab-<name>", "deck_name": "My Deck", "card_count": 42,
     "cards": [{ "word": "俳優", "reading": "はいゆう", "meanings": ["actor"],
                 "jlpt": "N2", "category": "theater", "context": "..." }] }
   ```
2. `python3 pipeline/build.py` — deck auto-appears under Vocabulary on Home.

Progress is keyed by `word`. Mixed kanji+vocab decks are not supported.

### Reorder cards

Change the emission order in `build_decks.py` (or the source JSON for Integrated chapters) and rebuild. New-card intake respects deck order, capped by `newPerDay`.

### Storage reliability — solving the eviction problem

**The issue:** Safari evicts PWA localStorage for origins unused for ~7 weeks. The current 30-day export reminder mitigates data loss but doesn't prevent it — if a user ignores the banner or is away 7+ weeks, progress is gone.

**Option A — iCloud sync via CloudKit JS (best for a solo iOS app)**
Use Apple's CloudKit JS SDK to sync the progress JSON to the user's private iCloud container. Free for end-users, no server needed, works in a PWA without a native wrapper.
- Effort: ~1 day. Add CloudKit JS CDN call + `saveState`/`loadState` wrappers that mirror to CloudKit.
- Tradeoff: Apple-only. Requires enrolling in the Apple Developer Program ($99/year) to provision a container, even for a free PWA.

**Option B — Cloudflare KV + a tiny auth token (best low-cost cross-platform)**
On first launch, generate a UUID device token stored in localStorage. On every `saveState`, POST the JSON to a Cloudflare Worker that writes it to KV under that token. On `loadState`, GET it back. Add a "link this device" QR code flow if you want multi-device.
- Effort: ~half a day. Cloudflare Workers + KV free tier (100k reads/day) is more than enough.
- Tradeoff: Progress is keyed to the token, not an account — if localStorage is already cleared the token is gone too. Mitigate with a "save my token" code shown in Settings.

**Option C — Capacitor native wrapper (eliminates the problem entirely)**
A native WKWebView wrapper uses the app's sandboxed storage, which iOS never evicts. Also unlocks haptics, push notifications, and App Store distribution.
- Effort: ~2 days to wire up Capacitor, then $99/year Apple Developer for distribution.
- Tradeoff: Biggest lift; overkill if the eviction risk is acceptable given the export reminder.

**Recommendation:** Start with **Option B** (Cloudflare KV). It's an afternoon of work, free, and solves the eviction problem without requiring Apple enrollment. Add Option A later if you want seamless iCloud sync alongside the App Store path.

## Things to know before going native (Stage 3)

- **Storage eviction:** Safari may clear localStorage for sites unused ~7 weeks. See roadmap above for mitigation options.
- **Push notifications** — only work reliably in a native wrapper on older iOS. iOS 16.4+ supports them for installed PWAs.
- **Viewport / safe-area** — already handled in CSS. Re-verify after layout changes.
- **Schema migrations** — always bump `SCHEMA_VERSION` and add a migration before changing the persisted state shape. Old exports continue to work.
- **Content** — kanji data is Creative Commons (KANJIDIC2 / JMdict). Etymology/keyword text is AI-generated — disclose if submitting to App Store.
- **Cost** — Stage 3 sideload: $0 (7-day cert). App Store: $99/year Apple Developer Program.
